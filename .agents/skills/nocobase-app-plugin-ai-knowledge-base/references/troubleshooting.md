# Troubleshooting

Work down the dependency chain — embedding service, vector database, disk, knowledge base, documents, employee — and stop at the first broken link. Read the server log from the latest start first: configuration and Manifest problems are warnings there, never failed starts.

## Startup and configuration

| Symptom                                                                                              | Cause                                                                                                                                                                                                            | Fix                                                                                                                                                                          |
| ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A vector database change in `config.yml` never takes effect, or the record is missing                | the entry is invalid and was skipped: missing or duplicate `key`, `connectProps` instead of `connection`, an empty `host`/`user`/`database`, a bad `port` or `tableName`, or a `${NAME}` whose variable is unset | read the startup log for `Invalid vector database configuration was skipped.`; fix the entry; set the variable where the server starts — `.env` counts only under `pnpm dev` |
| App fails to start: `Add JobExecutorServiceProvider from @nocobase/app-server/jobs to server/app.ts` | the App does not compose the jobs service                                                                                                                                                                        | add `JobExecutorServiceProvider` to `server/app.ts` and the `jobs` section to `server/config/index.ts`, as the default template does                                         |
| App fails to start resolving the AI manager                                                          | AI Employee plugin not registered                                                                                                                                                                                | register `@nocobase/app-plugin-ai-employee` before this plugin in both `plugins.ts` files                                                                                    |
| Vector database missing from AI settings                                                             | wrong nesting (must be `ai.aiKnowledgeBase.vectorDatabases`), or a manual record holds the same key                                                                                                              | fix the YAML; delete the manual record or change the key; check the log                                                                                                      |
| Configured vector database cannot be edited or deleted                                               | expected: it is `managedBy: config`                                                                                                                                                                              | edit `config.yml`                                                                                                                                                            |
| Vector database removed from `config.yml` is still listed                                            | a knowledge base still references it                                                                                                                                                                             | move or delete those knowledge bases first                                                                                                                                   |
| LLM service missing from the knowledge-base form                                                     | service disabled, its provider does not embed, or a mistyped `provider` dropped it                                                                                                                               | see [embedding-services.md](embedding-services.md#which-providers-can-embed)                                                                                                 |
| Disk missing from the form                                                                           | not on the allowlist, or the allowlist changed without a restart                                                                                                                                                 | see [storage-disks.md](storage-disks.md#the-allowlist); restart                                                                                                              |
| Manifest did nothing                                                                                 | it already succeeded once, the App was only reloaded rather than restarted, or it failed with a warning                                                                                                          | read the log; see [manifests.md § What a restart does](manifests.md#what-a-restart-does)                                                                                     |
| Manifest fails the same way on every start after the YAML was fixed                                  | a validated Manifest re-runs its stored snapshot; YAML edits are ignored                                                                                                                                         | write the corrected Manifest at a new location                                                                                                                               |

## Knowledge base and upload

| Symptom                                               | Cause                                                                | Fix                                                                                         |
| ----------------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `401 AUTHENTICATION_REQUIRED`                         | no session or token                                                  | sign in; send the App's session or API token                                                |
| `403 AI_SETTINGS_ACCESS_REQUIRED`                     | the role lacks `page:ai.settings` / `access`                         | grant it through the authorization Skill, or use an administrator                           |
| `400 VECTOR_CONFIG_REQUIRED`                          | one of the three vector fields is empty                              | send `vectorDatabaseKey`, `llmService` and `embeddingModel`                                 |
| `400 STORAGE_DISK_NOT_ALLOWED`                        | disk not on the allowlist                                            | allowlist it and restart, or pick a listed disk                                             |
| `400 UNSUPPORTED_FILE_TYPE` / `413 UPLOAD_TOO_LARGE`  | extension not accepted / over 100 MiB                                | convert the file (for example to `.pdf` or `.md`) or split it                               |
| `415 UNSUPPORTED_UPLOAD_CONTENT_TYPE`                 | not `multipart/form-data`, or no boundary                            | send a multipart body with exactly one `file` field                                         |
| `400 LOCAL_KNOWLEDGE_BASE_REQUIRED`                   | uploads and segment changes on a READONLY or EXTERNAL knowledge base | use a LOCAL knowledge base                                                                  |
| `409 TABLE_ALREADY_EXISTS` creating a vector database | the table is already there                                           | choose another `tableName`, or confirm with the user and send `skipTableExistedCheck: true` |

## Documents

| Symptom                                                   | Cause                                                                                                                                                                                                                                            | Fix                                                                                                                                                                                         |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ERROR`: `does not support embeddings`                    | the knowledge base's service uses a provider without embeddings                                                                                                                                                                                  | point it at an embedding-capable service; re-vectorize                                                                                                                                      |
| `ERROR`: model not found / 404 / invalid model            | wrong `embeddingModel`, or the account cannot call it                                                                                                                                                                                            | prove a model id against the provider; update the knowledge base; re-vectorize                                                                                                              |
| `ERROR`: 401 / `apiKey is required` / authentication      | the key did not reach the server — unset variable, `.env` outside `pnpm dev`, rotated key                                                                                                                                                        | fix where the key lives and restart; re-vectorize                                                                                                                                           |
| `ERROR`: `LLM service "<name>" not found`                 | the service was renamed or removed from `ai.llmServices`                                                                                                                                                                                         | restore the name, or point the knowledge base at another service and re-vectorize                                                                                                           |
| `ERROR`: permission denied to create extension / relation | the PostgreSQL role cannot create the extension or table                                                                                                                                                                                         | have an administrator run `CREATE EXTENSION vector` and grant table creation                                                                                                                |
| `ERROR`: `different vector dimensions`                    | two embedding models share one table                                                                                                                                                                                                             | one table per model; move one knowledge base to its own vector database and re-vectorize                                                                                                    |
| Document stays `PENDING` or `PROCESSING`                  | the list was not reloaded; another job for the same document holds its lease (a live one finishes, a dead one's lease expires after two minutes); or, with several instances on the `memory` jobs adapter, the job was queued in another process | reload; wait; read the log for `Knowledge base vectorization job failed.`; restart the App, which queues unfinished documents again; use a `redis` jobs configuration for several instances |
| `ERROR` after a restart that "should have fixed it"       | restarting never retries finished documents                                                                                                                                                                                                      | re-vectorize the `ERROR` documents                                                                                                                                                          |
| Few or no segments, or a loader `ERROR`                   | no extractable text — a scanned PDF, an image-only slide deck                                                                                                                                                                                    | supply a text-based version of the document                                                                                                                                                 |

## Retrieval and the employee

| Symptom                                                                | Cause                                                                                                                                               | Fix                                                                                   |
| ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Hit test with a sentence copied from a document returns nothing        | document not `SUCCESS`, knowledge base disabled, or vectors written with another model or table                                                     | fix the upstream link; do not lower `Score` first                                     |
| Hit test works, the employee ignores the documents                     | knowledge base not enabled on the employee, the selection lists other or disabled knowledge bases, or `{knowledgeBaseData}` removed from the prompt | enable it, fix the selection (empty means every enabled one), restore the placeholder |
| The employee answers from documents only sometimes                     | `Retrieve on demand` lets the model decide                                                                                                          | switch to `Automatically retrieve for every question` when every answer needs them    |
| Retrieval stopped after changing the vector database, service or model | existing vectors belong to the old settings                                                                                                         | re-vectorize every document of the knowledge base                                     |
| Results are relevant but truncated or too broad                        | chunk size                                                                                                                                          | regenerate the documents with other segment options                                   |

## Server log messages

All come from module `ai-knowledge-base`.

| Message                                                                        | Meaning                                                                                            |
| ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| `Invalid vector database configuration was skipped.`                           | one entry failed validation; `path` and `problem` say where and why; its record was left unchanged |
| `Vector database configuration could not be synchronized after a reload.`      | a reload's synchronization failed, usually on the database; the previous records stay              |
| `Configured vector database conflicts with a manually managed record.`         | a manual record owns the key; the configured entry was skipped                                     |
| `Configured vector database was removed from config but is still referenced.`  | kept because knowledge bases reference it; the log lists them                                      |
| `Knowledge base Manifest source could not be loaded.`                          | the Manifest object is missing, unparsable or invalid; nothing was stored                          |
| `Knowledge base Manifest processing failed.`                                   | the target knowledge base could not be prepared; the message says why                              |
| `Knowledge base Manifest file import failed.`                                  | one listed file could not be imported; the others continued                                        |
| `Failed to delete knowledge base vectors; continuing knowledge base deletion.` | a deleted knowledge base may have left rows in the vector table                                    |
