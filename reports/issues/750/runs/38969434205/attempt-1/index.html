问题 01 · 实现阶段

Ticket write-field lists fail ESLint with a redundant type intersection

本任务已处理

server/itsm/resources.ts lines 58, 66, 77 and 91 reported @typescript-eslint/no-redundant-type-constituents: `string` is overridden by the ServiceTicketRow key union in the intersection type `keyof ServiceTicketRow & string`.

原因（实现者自述）
ServiceTicketRow declares only string-named fields, so `keyof ServiceTicketRow` is already a subset of string. Intersecting it with `string` collapses and the rule reports the redundant `string` constituent.
处理方式
Changed the four `satisfies readonly (keyof ServiceTicketRow & string)[]` clauses to `satisfies readonly (keyof ServiceTicketRow)[]`, which still validates every listed write field against the row interface. Repo-wide `eslint . --max-warnings 0` passes.
影响 / 代价：未提供，不估算来源：Agent · retro.json
问题 02 · 实现阶段

server/itsm declarations did not type-check

本任务已处理

tsconfig.server.json reported TS2322 at server/itsm/record-access.ts:74 (rows.map((row) => row.id) returned unknown[] instead of number[]) and TS2314 at server/itsm/resources.ts:237 (CompositeResourceReference requires one type argument).

原因（实现者自述）
The Kysely query result row is untyped, so `id` is `unknown`; and the authorization package now makes CompositeResourceReference generic over CompositeResourceActions.
处理方式
Typed the selected id in the map callback (`row.id as number`) and declared the return type as `CompositeResourceReference<CompositeResourceActions>` with the type imported from @nocobase/authorization/core. `pnpm exec tsc -p tsconfig.server.json --noEmit` passes.
影响 / 代价：未提供，不估算来源：Agent · retro.json

问题 04 · 修复阶段

Sample data silently never registered

本任务已处理

Signing in as the sample users employee/dispatcher/engineer returned 401 INVALID_USERNAME_OR_PASSWORD even with APP_SAMPLE_DATA=true, so no demo tickets or role users existed.

原因（实现者自述）
registerItsmSampleData ran in ItsmProvider.register() and used app.container.resolveIfCreated(sampleDataToken). The sample-data service is registered by the database provider, whose register() can run after an application provider's, so the token did not exist yet and the call returned undefined without recording anything.
处理方式
Moved registerItsmSampleData into ItsmProvider.boot(). All providers have registered by boot and the application runs the registered samples after every provider is ready, so the sample is both registered in time and still executes with the full container. Verified with `pnpm nocobase db sample` (lists itsm/service-desk) and by signing in as all three role users and reading their scoped ticket lists.
影响 / 代价：未提供，不估算来源：Agent · retro.json
问题 05 · 修复阶段

Ticket API routes answered under a doubled prefix

本任务已处理

The documented GET /api/tickets returned 404 while GET /api/tickets/tickets answered the list; Swagger showed /api/tickets/tickets.

原因（实现者自述）
The contribution's createRouter mounted an inner router that already declared `/tickets` at `router.route('/tickets', routes)`. defineApiRoutes contributions are themselves mounted at `/api`, so the segment appeared twice.
处理方式
Changed the mount to `router.route('/', routes)` and added tests/logic/itsm-route-mount.test.ts, which requests `/tickets` on the contributed router and asserts 200 with the list payload.
影响 / 代价：未提供，不估算来源：Agent · retro.json
问题 06 · 修复阶段

Datetime field filtered with the string builder

本任务已处理

GET /api/tickets/dashboard and GET /api/tickets/engineers returned 400 with RepositoryError: Filter group "string" does not match Field "disabledAt" of type "datetime".

原因（实现者自述）
listEngineers() used f.string('disabledAt').empty() on the datetime column that records a deactivated user.
处理方式
Changed both occurrences to f.date('disabledAt').empty(). Verified the dashboard and engineers endpoints return 200 at runtime.

问题 07 · 修复阶段

Wildcard auth middleware leaked into unrelated API contributions

本任务已处理

tests/logic/app-server.test.ts failed: GET /api/articles, /api/example and /api/routesExample returned 401 instead of the expected JSON 404 ROUTE_NOT_FOUND.

原因（实现者自述）
The ticket router registered `routes.use('*', auth.required())` and then mounted that inner router at the contribution root. The application merges every API contribution into one `/api` router, and Hono copies a mounted sub-router's middleware into the parent, so the wildcard authenticated every contribution mounted after the tickets.
处理方式
Scoped the guard to the paths the contribution owns — `routes.use('/tickets', required)` and `routes.use('/tickets/*', required)`. Added a test that merges the ticket router into a parent and asserts a sibling path stays reachable, so the leak cannot return silently. Verified at runtime: anonymous /api/tickets is 401 while anonymous /api/articles is 404.
影响 / 代价：未提供，不估算来源：Agent · retro.json

建议 01 · pipeline

Surface lint and type failures in the same verification round

可自动化

The verification run stopped at lint and hid two real TypeScript errors in the same new files. A repair agent that only reads the reported lint failure leaves the next round to rediscover them.

建议改动

Run the type check alongside or before lint and aggregate both results into one failure report, or let lint continue so all static checks report in a single round.

来源：Agent · retro.json

建议 02 · framework

A route contribution should not be able to authenticate another contribution

可自动化

Registering `router.use('*', auth.required())` inside an API contribution silently widened the guard to every contribution mounted after it, because the application merges all API contributions into one router and Hono copies mounted middleware into the parent. The failure appeared in an unrelated template test, far from the code that caused it.

建议改动

Have app-server reject or warn at start when an API contribution registers middleware whose resolved path is `*` (or otherwise escapes the paths the contribution also defines), and document that guards belong on the exact owned paths.

来源：Agent · retro.json

建议 03 · 验收机制

A sample-data check must start from a fresh install

可自动化

Sample data only runs when the default connection is installed with app.sampleData set, then is recorded as skipped on every later start. A verification that reuses an existing development database therefore reports no sample data without the sample code being at fault, which is exactly how this round's missing users first appeared.

建议改动

When a task declares sample data, have the runtime verification install against a fresh database (or run `nocobase db sample`) before asserting the sample users and records exist.

来源：Agent · retro.json

原始验收要求

我是IT服务台负责人，需要一个公司内部报修系统。员工提交问题、紧急程度和截图，服务台分派给工程师，工程师记录处理过程和解决办法，员工确认解决后关闭；仍未解决可以退回继续处理。 员工只看自己的工单，工程师只处理分派给自己的工单，服务台查看全部。新分派和处理结果及时通知相关人员，点击通知可以进入对应工单；超过24小时未解决时提醒服务台。首页展示待分派、超时工单和各工程师的工作量。

实际操作

  1. 以 Super Admin/服务台账号(dispatcher@example.com)确认首页：角色=Service desk，待分派 3、超时 0，工程师工作量表列出 Bob Engineer。
  2. 以员工 Alice(employee@example.com) 通过 /main/tickets/new 表单真实提交工单 1“Laptop will not start”(紧急程度 High，上传 sample.png 截图，POST /api/tickets 201、/api/ticketAttachments/uploadMany 201)，提交前截图为 c01-employee-new-ticket.png。
  3. 以 Alice 再提交工单 2“VPN disconnects every 10 minutes”(medium) 与工单 3“Email account locked out”(urgent，保持未分派)。
  4. 以服务台 Carol(dispatcher@example.com) 提交工单 4“Printer on floor 3 out of toner”，作为非 Alice 请求人的隔离样本。
  5. 服务台在工单 1 详情页用“Assign to an engineer”选择 Bob Engineer 并点击 Assign(POST /api/tickets/1/assign 200)，工单状态 Pending→Processing，工程师=Bob Engineer。
  6. 服务台同样将工单 2 分派给 Bob（POST /api/tickets/2/assign 200）。
  7. 服务台打开 /main/inbox 看到 4 条“New service ticket”通知；点击其中“Laptop will not start”通知的标题链接，地址跳转到 /main/tickets/1，证明点击通知可进入对应工单。
  8. 以工程师 Bob(engineer@example.com) 登录并完整重新加载：仪表盘角色=Engineer、工程师工作量 2 active/0 resolved；工单列表仅出现被分派的工单 1、2。
  9. Bob 的 /main/inbox 收到两条“Ticket assigned to you”通知（工单 1、2）。
  10. Bob 在工单 1 记录处理过程“Confirmed the mainboard power rail was dead...”，调用 POST /api/tickets/1/process 200；再填写解决办法并 Resolve(POST /api/tickets/1/resolve 200)，状态→Resolved，历史记录出现 progress 与 resolve 两条。
  11. Bob 直接打开 /main/tickets/3 与 /main/tickets/4：页面显示“This ticket could not be loaded.”，且 GET /api/tickets/3、/api/tickets/4 均返回 404 TICKET_NOT_FOUND，证明工程师看不到未分派/非本人请求的工单。
  12. 以 Alice 登录：工单列表仅显示自己的 3 条工单(1 Laptop=Resolved、2 VPN=Processing、3 Email=Pending)，查看不到服务台提交的工单 4（GET /api/tickets/4 → 404）。
  13. Alice 的 /main/inbox 收到“Your ticket has been resolved”通知；点击通知标题链接跳转到 /main/tickets/1。
  14. Alice 在工单 1 点击“Confirm and close”(POST /api/tickets/1/confirm 200)，状态→Closed，历史出现 confirm“Resolution confirmed.”。
  15. 退回返工流程：Bob 对工单 2 记录处理过程并 Resolve(200)；Alice 打开工单 2 在“Still not fixed”填入退回原因并点击“Return for more work”(POST /api/tickets/2/return 200)，状态 Resolved→Processing，历史出现 returned。
  16. Bob 的 /main/inbox 收到“Ticket returned for more work”以及工单 1 的“Ticket confirmed and closed”通知。
  17. Bob 对工单 2 再次记录处理过程并 Resolve(200)，状态→Resolved；Alice 再次收到解决通知并“Confirm and close”(POST /api/tickets/2/confirm 200)，状态→Closed；工单 2 历史完整呈现 submitted→assigned→progress→resolved→returned→progress→resolved→confirmed 八条。
  18. 服务台复核首页：待分派 2（工单 4 Printer、工单 3 Email），超时 0，工作量表 Bob Engineer 0 active/0 resolved（两单已关闭）；/main/tickets 可见全部 4 单(2 Closed、2 Pending)。
  19. 尝试合法触发超时提醒：探测 /api/serviceTickets:list|get|update、/api/itsm:serviceTickets、/api/sampleData:run、/api/app:runSampleData、/api/notifications:list、/api/tickets/overdue|runOverdueReminders|remind 等均 404/400，无回填 submittedAt 或手动触发提醒的浏览器入口。
