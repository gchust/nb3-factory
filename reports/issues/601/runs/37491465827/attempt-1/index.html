建议 01 · code-quality

`as never` casts hid an inference mismatch instead of a type error

可自动化

server/authorization/resources.ts used `as never` in six record-access resolvers and on the composite registration call. The lint rule proved the resolver assertions unnecessary and removing one of them exposed that `define(resource)` could not accept the union of builder types. The runtime intent was already `build()`-based, so the casts were masking an avoidable generic-inference problem.

建议改动

Prefer passing the concrete built value (`resource.build()`) or annotating the collection with the framework's accepted parameter type instead of `as never`.

来源：Agent · retro.json

建议 02 · 工具与构建

No guard against .js relative imports from source-loaded seeds and migrations

可自动化

server/** may import .js because it runs from compiled dist, but database/** seeds and migrations are dynamically imported from TypeScript source by the app-server task loader, where Node's native type stripping resolves only .ts specifiers. A .js specifier pointing at a .ts file compiles and only fails at application startup with ERR_MODULE_NOT_FOUND.

建议改动

Add a lint or check for relative imports under database/** that requires the .ts extension (or teach the seed/migration loader to resolve .js to .ts) so the mistake fails at author time rather than at runtime.

来源：Agent · retro.json

建议 03 · code-quality

A startup registration function existed but had no call site

需人工判断

server/authorization/resources.ts exported registerServiceAuthorization(), but nothing invoked it. The omission was invisible until seeded grants were validated in AuthorizationProvider.start(), which then failed on every composite action. The declarations were correct; only the lifecycle hook was missing.

建议改动

When a module exports a register*/define* function meant to run at startup, wire it to a named ServiceProvider in the same change, or export the provider instead of a bare function.

来源：Agent · retro.json

建议 04 · i18n

A key used by a component but absent from en-US is caught only by a test

可自动化

en-US is the source-of-truth locale shape, so zh-CN is typed against AppResource and a missing key there is a compile error. A key present in neither locale, however, compiles and is only caught by tests/logic/app-locale-coverage.test.ts.

建议改动

Optionally type component translation keys against AppResource or add a check that every t() key exists in en-US, so a missing key fails at build time.

来源：Agent · retro.json

建议 05 · 工具与构建

Source-loaded database tasks must use .ts specifiers, and the fix regressed

可自动化

Repair 2 had fixed database/main/seeds/..._create_service_permission_sets.ts and database/seed-data/permission-sets.ts to import .ts, because seeds and migrations are dynamically imported from TypeScript source (Node type stripping) where a .js specifier pointing at a .ts file throws ERR_MODULE_NOT_FOUND. Repair 3 rewrote both back to .js, so the seed-load failure returned in tests/logic/app-server.test.ts. The tsconfigs already allow importing .ts and rewrite it on emit, so the guard below would have caught it.

建议改动

Add a lint/check that relative imports under database/** must use the .ts extension (and the opposite, .js, under server/**), so this recurring mistake fails at author time.

来源：Agent · retro.json
