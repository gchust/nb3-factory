问题 01 · implement

应用完全没有资料库实现

本任务已处理

浏览器验收中 /main/drafts、/main/documents/1、/main/confidential 都重定向到 /main 模板首页；数据库无 documents 表、无 P/D/C、无甲/乙账号，侧栏无资料或用户管理入口。

原因（实现者自述）
仓库处于模板原始状态，实现从未生成或提交（不是回归）。
处理方式
新增迁移 202610200001_create_documents 创建 documents/documentShares；新增 server/documents/service.ts 领域规则、server/providers/documents.ts 服务提供者、server/routes/documents.ts 与 schemas.ts 并注册进 server/providers/index.ts、server/routes/index.ts；新增两个非 sample 种子创建权限集和账号/资料；新增 client/pages/documents/*、client/pages/users/index.tsx，在 client/routes.ts 注册路由与导航，并补齐 client/locales 词条；新增 tests/logic/document-library.test.ts。
影响 / 代价：未提供，不估算来源：Agent · retro.json

问题 03 · 自动验证

进程内测试的写请求被 CSRF 拒绝

本任务已处理

tests/logic/document-library.test.ts 中 editor POST /api/documents 返回 403 INVALID_CSRF_ORIGIN（0ms，未进入处理器），浏览器同源请求不会。

原因（实现者自述）
app-plugin-authentication 的 auth.required() 对携带 cookie 的写请求校验 Origin 是否为受信来源；createTestApp 的进程内请求默认不带 Origin。
处理方式
测试 helper 统一带 origin: http://localhost，并在 createTestApp 配置 app.publicOrigin 使该来源受信；同时补充 findUndeclaredApiRoutes/findApiDocumentSchemaProblems 断言。
影响 / 代价：未提供，不估算来源：Agent · retro.json
问题 04 · 自动验证

Permission Set 标题列必须存 JSON

本任务已处理

以原始字符串写 authorization_permission_sets.title 时，授权 provider 启动阶段 JSON.parse 抛 SyntaxError，应用无法启动。

原因（实现者自述）
Permission Sets store 读取时对 title 做 decodeAuthorizationTitle（JSON.parse），写入时做 encodeAuthorizationTitle。
处理方式
种子改为写 title: JSON.stringify(title)，页面按解码后的纯文本显示标签。
影响 / 代价：未提供，不估算来源：Agent · retro.json

实现者补充建议

来自可选过程笔记，不代表已独立确认；相同建议引用上方评审，其余保留原文。

建议 01 · testing

进程内测试客户端应模拟浏览器来源

可自动化

createTestApp 的 app.request 直连应用，不经过浏览器，因此缺少 Origin，任何依赖 cookie 的写请求都会被认证插件的 CSRF 保护拒绝，表现为与业务无关的 403。

建议改动

为 @nocobase/app-testing 的请求 helper 增加可选的 origin 参数（或在测试模板中默认带 Origin 并配置 publicOrigin），让写请求测试开箱可用。

来源：Agent · retro.json

建议 02 · seeds

区分必需种子与示例种子以免示例数据缺失

需人工判断

验收环境的 APP_SAMPLE_DATA 未设置，defineSeed({ sample: true }) 不会加载；但本任务的示例账号和资料属于验收必需数据，只能写成非 sample 种子，与“示例数据不应进入生产初始化”的常规指引存在张力。

建议改动

在应用种子文档中明确：验收/演示所需但业务上必需的数据应使用非 sample 种子，并在种子注释里说明该取舍。

来源：Agent · retro.json

建议 03 · authorization

Permission Set 标题的存储格式需要文档化

可自动化

authorization_permission_sets.title 实际存储 JSON 编码后的值，直接用 SQL/Kysely 写库时容易写入原始字符串，导致读取端 JSON.parse 失败并使 provider 启动报错。

建议改动

在 authorization 插件 Skill 中给出用 Kysely 直接写权限集时的正确 title/grants 编码示例。

来源：Agent · retro.json
