问题 01 · repair-2

Internal document library feature entirely absent

本任务已处理

After signing in as the administrator, the sidebar had only Home; /main/api/users returned only nocobase; no 资料库 list, detail page, share/revoke action, confidential field, or account-disable flow existed, so all browser acceptance checks (B01-B05) failed.

原因（实现者自述）
The template baseline ships no business feature; the previous implementation attempt never wrote any application source, so migrations, seeds, server routes/providers, pages, navigation and locale keys were all missing.
处理方式
Implemented the feature end to end: migration 202610200001_create_material_library.ts (materials, material_shares, library_member_roles), required seed 202610200002_library_seed.ts (accounts jia/jia123456 and yiyi/yi123456, materials P/D/C), server/providers/library.ts (visibility: admin > owner > published-and-non-confidential members; confidential hidden from shares), server/routes/library.ts with declared and validated /api/library endpoints, client pages /materials, /materials/:materialId, /library-admin with navigation and zh-CN/en-US strings, and tests under tests/logic. Verified against a fresh database and a production server.

问题 02 · repair-2

Better Auth rejects cookie-authenticated writes in route tests

本任务已处理

Four route tests failed with 403 PERMISSION_DENIED reason INVALID_CSRF_ORIGIN on POST/PUT/PATCH/DELETE while GET tests passed.

原因（实现者自述）
Better Auth's checkCookieWriteOrigin requires a trusted Origin (or Referer) on cookie-authenticated non-GET requests; the test session's fetch added the session cookie but no Origin header, and the test config set no public origin.
处理方式
Set app.publicOrigin to the test origin in createAppTest config and added a small write() helper that sends a matching Origin header on non-GET requests, mirroring what a same-origin browser fetch sends.

单条临时共享与即时撤销

管理员在资料详情的 Temporary sharing 中按人开放草稿 D，乙获得只读访问；撤销后乙在原会话刷新或重开链接都只得到 Material not available，不会复用旧权限。

阅读不等于编辑

后台停用账号使旧会话失效

管理员在资料库管理页停用乙后，乙原有登录会话访问业务页被重定向到登录页；甲的账号与负责的三份资料保持可用。
