Problems & resolutions

遇到的问题

Added the Pipeline Smoke page/route/navigation per the task. One verification test failed because its exact Client route-composition assertion had not been updated for the new route.

问题 01 · verification

inspect-client route composition test failed after adding /pipeline-smoke

已解决

tests/logic/inspect-client.test.ts > inspects configured Client contributions without running lifecycle or leaf loaders: expected 9 routes to deeply equal 10; received included nb3-factory:pipeline-smoke.

原因
The new application route was wired in client/routes.ts and reflected in tests/logic/client-routes.test.ts, but the exact-ordered route assertion in tests/logic/inspect-client.test.ts still listed only the original routes.
处理方式
Added the nb3-factory:pipeline-smoke { auth: 'required', path: '/pipeline-smoke' } entry between home and login in the expected list, matching the declared route and the inspection output order. Re-ran the three relevant test files: 12 tests passed.
影响 / 代价：未提供，不估算来源：Agent · retro.json
Improvement opportunities

可改进的点

为什么值得改、具体改哪里，以及能否自动化；与已经发生的问题和修复结果分开记录。

建议 01 · tests

Hardcoded route composition assertions need updating with new routes

可自动化

tests/logic/inspect-client.test.ts asserts the exact ordered list of Client routes. Adding /pipeline-smoke to client/routes.ts (and updating tests/logic/client-routes.test.ts) left this second list stale, so the full test run failed with a 10-vs-9 route mismatch.

建议改动

When adding a Client route, search tests/logic for exact route-list assertions (e.g. inspection.routes.map(...).toEqual([...])) and update every copy, or relax the snapshot to target only the routes under test.
