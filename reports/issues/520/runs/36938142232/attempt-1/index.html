建议 01 · 验收机制

Seed page-grant ids had no matching route

可自动化

建议改动

Add a logic test that reads every page grant id used by seeds and migrations and fails when no registered app route declares the same authz.resource.id.

不依赖 AI 服务即可验收：主管维护三条资料，普通同事只能阅读 A/B，C 的页面及直接读取接口均拒绝普通同事访问；刷新后资料仍保存。未配置模型时助手显示明确未配置状态，资料页仍可用。 以下 B01–B05 在独立业务测试模型配置可用后执行；缺模型时逐项记 blocked，继续完成资料、权限、助手接入和未配置状态的搭建，不用固定回复替代真实调用。

实际操作

  1. 以管理员 nocobase 登录 http://127.0.0.1:13000/main/，进入 Document library，确认三条资料 A/B/C 均在列表中并带 Edit/Delete。
  2. 管理员打开资料 B 的 Edit document 弹窗，确认 Title/Content 原值正确回填，将巡检间隔由 45 天改为 60 天并点击 Save，页面出现 Document saved；刷新后列表仍显示 60 天。
  3. 管理员打开 Document assistant，确认显示 The assistant is unavailable / The AI service is not configured / No AI model is enabled，并可通过 Open the document library 回到资料页。
  4. 退出并以普通同事 colleague 登录，session 确认为 colleague@example.com；进入 Document library 仅见 A/B 两行、无 C、无 Edit/Delete 操作列。
  5. 以 colleague 浏览器会话实际调用接口：POST documentsMaterials:findMany 返回 doc-a/doc-b 两条；POST findOne(filter id=doc-c) 返回 {"data":null}；POST findMany(filter id=doc-c) 返回 {"data":[]}；POST createOne 返回 403 FORBIDDEN。
  6. 以 colleague 直接打开 /main/materials/doc-c，URL 被重定向到 /main，页面未出现任何 C 内容。
  7. 以 colleague 打开 Document assistant，显示未配置/不可用状态，点击 Open the document library 可正常进入资料页；刷新资料页后 A/B 仍在（B 为 60 天）。
  8. 退出并以资料主管 supervisor 登录，session 确认为 supervisor@example.com；Document library 显示 A/B/C 三条且带 Edit/Delete；接口 findMany 返回三条，findOne(doc-c) 返回 C 的内容。
