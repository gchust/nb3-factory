问题 01 · 实现阶段

上一轮实现未产出任何业务代码，浏览器验收 B01–B05 全部失败

本任务已处理

验收报告显示应用可登录，但主导航只有 Home，首页为 Start building your application，用户管理只有 Super Admin，权限集只有 Member 与 System administrator，数据库无资料相关集合；不存在资料 P/D/C 与甲、乙账号。

原因（实现者自述）
实现 Agent 在探索模板结构与既有能力时耗尽上下文，停在调查阶段即结束，既没有写入 database/、server/、client/ 下的任何业务代码，也没有验证。
处理方式
本轮从零实现：迁移创建 materials/materialShares，种子写入 curator/reader 权限集、甲/乙账号与 P/D/C 资料，server/providers/materials-service.ts 承载访问规则，server/routes/materials.ts 暴露 REST 接口，client/pages/materials/ 提供列表与详情页与管理员临时开放面板。
影响 / 代价：整轮修复时间；浏览器验收需重新运行才能确认。来源：修复阶段 · 第 1 轮
问题 02 · 修复阶段

Better Auth 用户名最短 3 字符，乙的短用户名登录被 422 拒绝

本任务已处理

种子写入用户后，以短用户名登录返回 422，无法完成阅读者视角的验证。

原因（实现者自述）
认证插件的 username() 默认 minUsernameLength 为 3，种子最初选择的用户名过短，种子本身写入成功但登录被拒。
处理方式
用户名改为满足下限的 jia / yier，密码沿用 admin123；集成测试以真实登录流程覆盖两个账号。
影响 / 代价：少量调试时间。来源：修复阶段 · 集成测试
问题 03 · 修复阶段

Cookie 认证的写请求缺少受信任 Origin 时返回 403 INVALID_CSRF_ORIGIN

本任务已处理

集成测试中登录 GET 正常，POST/PATCH/DELETE 返回 403，reason=INVALID_CSRF_ORIGIN，表现为「接口存在但写不进去」。

原因（实现者自述）
应用以 Cookie 会话认证，写请求要求 Origin 与应用 publicOrigin 匹配；测试未发送 Origin 头。
处理方式
测试配置显式设置 app.publicOrigin，并在每个写请求上发送匹配的 origin；应用代码无需放宽校验。
影响 / 代价：一轮集成测试调试时间。来源：修复阶段 · 集成测试

建议 01 · 脚手架默认值

在任务模板中预置业务演示数据与工作权限集的种子样例

可自动化

本轮若不自行播种甲/乙账号与资料员/阅读者权限集，浏览器验收既无法切换角色也无法直接打开受保护页面，B01–B05 将无法执行。

建议改动

为「有角色、有演示数据」类需求提供一份 seed 样例：创建应用自有权限集并挂到用户管理可调整的作用域，同时写入最少量演示记录与账号。

来源：修复阶段 · 种子实现

建议 02 · Skill 与文档

应用开发 Skill 补充 createAppTest 的真实应用测试前置条件

可自动化

createAppTest 启动真实应用时若未设置 auth.secret 会抛 ApplicationNotConfiguredError，Cookie 写请求还需 Origin 与 app.publicOrigin 匹配，这两点只能从源码推断。

建议改动

在 testing 参考中给出最小可用配置片段（publicOrigin + auth.secret）与「写请求带 Origin」的说明，以及查询数据库已注册集合（database.collections().list()）的断言写法。

来源：修复阶段 · 集成测试

建议 03 · 验收机制

实现阶段应在写完全部业务代码后立即跑一次真实 HTTP 测试再结束

需人工判断

上一轮在调查阶段耗尽上下文，没有任何可验证产物，导致浏览器验收只能全项失败，也无法区分「未实现」与「实现错误」。

业务场景与交付说明

角色化资料访问

资料员甲可创建、编辑、删除自己负责的资料；阅读者乙只读已发布不保密资料 P，服务端拒绝其编辑请求。

单条临时共享与撤销

管理员在草稿 D 上仅向乙开放单条，乙可见但无编辑权；撤销后乙刷新或重开原链接均无正文，其他草稿仍不可见。

保密资料硬限制

即使管理员把保密资料 C 开放给乙，乙列表与直链仍不可见并返回 404，甲仍可正常读取 C。

停用即时失效

管理员停用乙后，乙已登录会话刷新即被登出；甲的账号与 P/D/C 资料不受影响。

原始验收要求

乙可以阅读 P 但不能编辑；甲可以维护自己的资料。

实际操作

  1. 以阅读者乙登录后打开 Document library，只看到已发布不保密的“公开资料 P”，且没有“New document”入口。
  2. 乙打开 P 详情，正文完整显示，页面只有返回列表链接，没有 Edit/Delete 按钮。
  3. 乙在页面内直接 PATCH /main/api/materials/material-public-p（content 字段），服务端返回 403 PERMISSION_DENIED / MATERIAL_FORBIDDEN（You may not edit this material.）。
  4. 退出后以资料员甲登录，Document library 显示自己负责的 P、D、C；打开 P 点 Edit，表单回填 Title=公开资料 P、Body=原文、Published 已勾选、Confidential 未勾选。
  5. 甲修改 P 正文并保存，详情正文与 Last updated 同步更新；随后甲把 P 正文还原为原文。
  6. 甲通过 New document 新建“私有草稿 D2”，owner 自动为甲，并在验证结束后删除，完成创建/编辑/删除的资料维护闭环。

观察结果

  1. 乙的 Document library 仅含“公开资料 P”，无 D/C/D2；乙的 P 详情没有 Edit/Delete 按钮。
  2. 乙对 P 的更新请求返回 403 MATERIAL_FORBIDDEN。
  3. 甲的列表含 P/D/C，Edit 表单原值正确回填；保存后正文与更新时间变化；甲可新建并删除自己的资料。

原始验收要求

乙原本不能打开 D；管理员开放 D 后，乙能查看 D，但没有获得编辑权限或其他草稿的访问权。

实际操作

  1. 乙（未开放前）的 Document library 不含“私有草稿 D”，直接打开 /main/materials/material-draft-d 显示“This document is not available”。
  2. 管理员在 D 详情的 Temporary access 中选择“阅读者乙”并点击 Open，页面出现“阅读者乙 Opened …/Revoke”，API shares 含乙。
