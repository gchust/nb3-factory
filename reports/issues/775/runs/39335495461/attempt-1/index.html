## Errors

Throw `ApiError` from `@nocobase/app-server/router`; the application renders it. Do not write an error body by hand.

```ts
import { ApiError } from '@nocobase/app-server/router';

throw new ApiError({
  status: 'NOT_FOUND',
  reason: 'ORDER_NOT_FOUND',
  domain: 'orders',
  message: `Order ${orderId} was not found.`,
});
```

Every failed `/api` response then has this body, with the same `requestId` in the `x-request-id` response header:

```json
{
  "error": {
    "code": 404,
    "status": "NOT_FOUND",
    "reason": "ORDER_NOT_FOUND",
    "domain": "orders",
    "message": "Order 42 was not found.",
    "requestId": "7f1c9a3e-…"
  }
}
```

- **`status`** is one of a fixed set, and decides the HTTP status. Pick the one that matches:

  | `status`              | HTTP | Use for                                                   |
  | --------------------- | ---- | --------------------------------------------------------- |
  | `INVALID_ARGUMENT`    | 400  | The request itself is malformed or a field is invalid     |
  | `FAILED_PRECONDITION` | 400  | The request is valid, but the resource's state forbids it |
  | `UNAUTHENTICATED`     | 401  | No valid session or API key                               |
  | `PERMISSION_DENIED`   | 403  | Not allowed                                               |
  | `NOT_FOUND`           | 404  | Allowed, but the resource does not exist                  |
  | `ALREADY_EXISTS`      | 409  | Creating something that already exists                    |
  | `ABORTED`             | 409  | A concurrent change won, such as a version conflict       |
  | `RESOURCE_EXHAUSTED`  | 429  | A rate limit or quota                                     |
  | `INTERNAL`            | 500  | Never thrown on purpose; the application answers it       |
  | `UNAVAILABLE`         | 503  | A dependency is down; retrying later may succeed          |

  Two HTTP statuses exist outside this table, both as an `INVALID_ARGUMENT` that passes `httpStatus`: `413` for a request body over a size limit the route sets or the application's `api.bodyLimit` and `415` for an unsupported request content type. Nothing else overrides the status, and neither covers anything else: a generated output that grows too large is `400 FAILED_PRECONDITION`, and a file with the wrong extension is `400 INVALID_ARGUMENT`. There is no `422`: an invalid request is `INVALID_ARGUMENT` and a valid one the state forbids is `FAILED_PRECONDITION`, both `400`. There is no `502`: a failing upstream is `503 UNAVAILABLE`.

- **`reason`** is what clients branch on: UPPER_SNAKE_CASE, unique within its domain, stable once released. A client never parses `message`.
- **`domain`** is the namespace of whoever defined the reason: the plugin namespace, or the application's name for its own routes. The framework uses `app`. A plugin has one domain even when it serves several URL prefixes: every AI knowledge base error is `aiKnowledgeBases`. An error passed through from another plugin keeps the domain of the plugin that defined its reason, so the users plugin passing on `LAST_ASSIGNMENT` answers with domain `authorization`.
- **`message`** is an English sentence for developers. It is never shown to users.
- **`localizedMessage`**, `{ locale, message }`, is optional user-facing text the handler has already translated with the request's i18n.
- **`fieldViolations`**, `[{ field, description }]`, names the invalid fields of an `INVALID_ARGUMENT`.

function deviceApiError(
  context: Context,
  options: {
    status: number;
    reason: string;
    message: string;
    key: string;
    params?: Record<string, unknown>;
  },
): ApiError {
  const locale = getRequestLocale(context);
  // Read rather than `getRequestTranslator()`, which throws without the i18n middleware: an error must still render.
  const translator = context.get(TRANSLATOR_CONTEXT_KEY) as
    Translator | undefined;
  const localizedMessage =
    locale && translator
      ? {
          locale,
          message: translator(options.key, {
            ns: APP_NS,
            ...options.params,
          }),
        }
      : undefined;
  return new ApiError({
    status: apiErrorStatusFromHttp(options.status),
    reason: options.reason,
    domain: 'devices',
    message: options.message,
    ...(localizedMessage ? { localizedMessage } : {}),
    ...(options.params ? { metadata: options.params } : {}),
  });
}

function codeTaken(context: Context, code: string): ApiError {
  return deviceApiError(context, {
    status: 409,
    reason: 'DEVICE_CODE_TAKEN',
    message: 'Another device already uses this code.',
    key: 'devices.errors.codeTaken',
    params: { code },
  });
}

function deviceNotFound(context: Context): ApiError {
  return deviceApiError(context, {
    status: 404,
    reason: 'DEVICE_NOT_FOUND',
    message: 'No device has this id.',
    key: 'devices.errors.notFound',
  });
}

function translateDomainError(context: Context, error: unknown): unknown {
  return error instanceof DuplicateDeviceCodeError
    ? codeTaken(context, error.code)
    : error;
}

原因（实现者自述）
验收环境的 WebSocket 域限制包装器替换了 window.WebSocket，但只保留构造行为，未保留标准静态常量 CONNECTING/OPEN/CLOSING/CLOSED。@nocobase 实时客户端用 socket?.readyState === WebSocket.CONNECTING / OPEN 判断状态；两边都是 undefined 时判断为 true，导致 connected 始终为 true，connect() 直接返回而从不创建 WebSocket。CDP 中可见失败页面没有任何 webSocketCreated 事件，而手工在页面主世界创建 WebSocket 可以正常握手。
处理方式
新增 client/lib/websocket-ready-state.ts，在 app.start() 前为缺失常量的 WebSocket 构造器补上标准值（已有数值时不覆盖），并加注释与单元测试。用验收浏览器重新登录、刷新并观察 CDP：/main/ws 正常创建并握手，页面进入首页；设备列表的增删改查、状态过滤和中英文切换也验证通过。另修正设备列表编辑链接为 /devices/edit/:deviceId 以匹配子路由，并同步组件测试。

- **`status`** is one of a fixed set, and decides the HTTP status. Pick the one that matches:

  | `status`              | HTTP | Use for                                                   |
  | --------------------- | ---- | --------------------------------------------------------- |
  | `INVALID_ARGUMENT`    | 400  | The request itself is malformed or a field is invalid     |
  | `FAILED_PRECONDITION` | 400  | The request is valid, but the resource's state forbids it |
  | `UNAUTHENTICATED`     | 401  | No valid session or API key                               |
  | `PERMISSION_DENIED`   | 403  | Not allowed                                               |
  | `NOT_FOUND`           | 404  | Allowed, but the resource does not exist                  |
  | `ALREADY_EXISTS`      | 409  | Creating something that already exists                    |
  | `ABORTED`             | 409  | A concurrent change won, such as a version conflict       |
  | `RESOURCE_EXHAUSTED`  | 429  | A rate limit or quota                                     |
  | `INTERNAL`            | 500  | Never thrown on purpose; the application answers it       |
  | `UNAVAILABLE`         | 503  | A dependency is down; retrying later may succeed          |

  Two HTTP statuses exist outside this table, both as an `INVALID_ARGUMENT` that passes `httpStatus`: `413` for a request body over a size limit the route sets or the application's `api.bodyLimit` and `415` for an unsupported request content type. Nothing else overrides the status, and neither covers anything else: a generated output that grows too large is `400 FAILED_PRECONDITION`, and a file with the wrong extension is `400 INVALID_ARGUMENT`. There is no `422`: an invalid request is `INVALID_ARGUMENT` and a valid one the state forbids is `FAILED_PRECONDITION`, both `400`. There is no `502`: a failing upstream is `503 UNAVAILABLE`.

- **`reason`** is what clients branch on: UPPER_SNAKE_CASE, unique within its domain, stable once released. A client never parses `message`.
- **`domain`** is the namespace of whoever defined the reason: the plugin namespace, or the application's name for its own routes. The framework uses `app`. A plugin has one domain even when it serves several URL prefixes: every AI knowledge base error is `aiKnowledgeBases`. An error passed through from another plugin keeps the domain of the plugin that defined its reason, so the users plugin passing on `LAST_ASSIGNMENT` answers with domain `authorization`.
- **`message`** is an English sentence for developers. It is never shown to users.
- **`localizedMessage`**, `{ locale, message }`, is optional user-facing text the handler has already translated with the request's i18n.
- **`fieldViolations`**, `[{ field, description }]`, names the invalid fields of an `INVALID_ARGUMENT`.
