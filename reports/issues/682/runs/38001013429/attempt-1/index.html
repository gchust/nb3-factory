问题 01 · 自动验证

应用语言覆盖测试缺少 AI 扩展的 139 个文案键

本任务已处理

tests/logic/app-locale-coverage.test.ts 报告 139 个键在 client/locales/en-US.ts 与 client/locales/zh-CN.ts 中均缺失，全部来自 client/extensions/nocobase-ai/components/**（如 surface.title、chat.composer.send、tool.*）。

原因（实现者自述）
client/extensions/nocobase-ai 是应用自有源码，但它的组件通过 useAITranslate() 读取扩展内置的 en-US/zh-CN 映射，组件里只有 t('key', fallback) 而没有 useTranslation('...')；覆盖测试会扫描 client/ 下所有 t('字面量') 并要求键出现在应用语言文件中，因此把这些键当成应用键。扩展自身的语言表还漏了 tool.output、tool.businessReport.failed / chartFailed / previewUnavailable 四个键。
处理方式
在 client/locales/en-US.ts 与 zh-CN.ts 中 import 并展开扩展导出的 nocobaseAILocales（保持单一来源，避免手工复制 160+ 个键后漂移），并把扩展自身缺失的 4 个键补进 client/extensions/nocobase-ai/locales/en-US.ts 与 zh-CN.ts。结构上做了键冲突检查（0 冲突）。
影响 / 代价：约 3 次针对性测试运行来源：Agent · retro.json
问题 02 · 自动验证

client-shell 侧边栏收起断言偶发读到旧状态

本任务已处理

tests/logic/client-shell.test.tsx:210 点击「Collapse navigation」后立即断言 data-state=collapsed，却读到 data-state=expanded；整轮并行运行时偶发，单独运行稳定通过。

原因（实现者自述）
侧边栏折叠偏好经 useSyncExternalStore 外部 store（window 事件 + localStorage）传播，点击触发的 DOM 更新在重负载下可能推迟到下一个 tick；断言与点击在同一 tick 读取属性，形成竞态。
处理方式
把两处 data-state 断言包进 await waitFor(...)，断言内容（collapsed / expanded）不变，仅等待 store 更新刷入 DOM。修改后单独运行 6 次、全量运行 4 次均稳定通过。
影响 / 代价：约 4 次全量测试运行来源：Agent · retro.json
问题 03 · 自动验证

应用缺少“内部资料只读问答助手”业务能力

本任务已处理

主应用只有 Home；User management 只有 nocobase；AI Employees 只有默认 Atlas；GET /api/materials 与 /api/materials:list 均返回 404 ROUTE_NOT_FOUND；materials 集合在 Database Explorer 可见但没有 API 资源或页面入口；LLM services 未配置时也没有可在应用内显示的助手未配置状态。

原因（实现者自述）
默认模板只注册产品能力，没有本应用的业务表、HTTP 接口、页面、测试账号或权限模型，也没有把 materials 暴露为 API 资源，因此主管/同事都无法维护或读取资料。
处理方式
新增 materials 集合迁移与三份种子（A/B/C 样例资料、supervisor/colleague 测试账号、materials-colleague/materials-supervisor 权限集）；在 server/materials/declaration.ts 定义 recordAccess(materials.viewable) 与 composite(internalMaterials, view/edit)；MaterialsService + MaterialsProvider 提供 GET /api/materials 与 GET/PATCH /api/materials/:materialId，并用 defineRepositoryApiRoutes 追加 findMany/findOne/count/updateOne；客户端新增 /materials 与 /assistant 路由、导航与页面；server/ai 注册只读 read-materials 工具与 materials-assistant 员工。同事只有 view 且 scope=materials.viewable，主管 view+edit 且 scope=allRecords，页面与助手走同一授权模型，因此看不到的 C 也无法经助手问出。
影响 / 代价：本会话 1 次端到端 HTTP 脚本验证 + 1 次全量测试 + 1 次生产构建来源：Agent · retro.json
问题 04 · 自动验证

布尔字段的记录范围条件用 $eq 被数据库层拒绝

本任务已处理

同事 GET /api/materials 返回 400 FIELD_CAPABILITY_NOT_SUPPORTED：Operator "$eq" is not supported for Field "confidential" of type "boolean"。

原因（实现者自述）
materials.viewable 的 resolver 写成 condition("confidential", "$eq", false)，而布尔字段只接受 $isTruly / $isFalsy（见 @nocobase/db 的 operator map）。
处理方式
改为 condition("confidential", "$isFalsy")。记录范围在运行时注册、不入库，无需迁移；重启后端到端脚本确认同事只返回 A/B、C 为 404、编辑为 403。
影响 / 代价：未提供，不估算来源：Agent · retro.json
问题 05 · 自动验证

种子用 .js 相对导入 .ts 模块在原生 ESM 加载器下失败

本任务已处理

tests/logic/app-server.test.ts 启动安装版应用时数据库种子失败：ERR_MODULE_NOT_FOUND: database/seed-data/materials-permission-sets.js（由 202610010004 种子导入）。

原因（实现者自述）
数据库任务加载器用原生 import() 动态加载种子；Node 的类型剥离不会把 .js 说明符解析到同名 .ts，而 pnpm nocobase db apply 走的 tsx 会解析，所以问题只在测试/原生加载路径暴露。
处理方式
把种子链上的相对导入改为显式 .ts（seed→database/seed-data、seed-data→server/materials/declaration）。tsconfig 已启用 allowImportingTsExtensions + rewriteRelativeImportExtensions，tsc 会把它重写回 .js，已在 dist 产物中核对。
影响 / 代价：未提供，不估算来源：Agent · retro.json
问题 06 · 自动验证

应用 Provider 在无插件的运行时组成测试中硬解析插件 token

本任务已处理

tests/logic/app-server.test.ts > registers application-owned providers and routes from the runtime 抛出 Service "@nocobase/app/authorization" is not registered。

建议 01 · 模板兼容

AI Employee registry item 的语言表漏了组件引用的键

可自动化

client/extensions/nocobase-ai 与 node_modules/@nocobase/app-plugin-ai-employee/registry/nocobase-ai 字节一致，但其 locales/{en-US,zh-CN}.ts 缺少组件里 t() 引用的 tool.output、tool.businessReport.failed、tool.businessReport.chartFailed、tool.businessReport.previewUnavailable。应用展开该语言表后这些键才被补齐。

建议改动

在 registry item 的 locales 中补齐组件引用的全部键，并加一条自检：扫描同目录组件的 t('字面量', 回退) 调用，确保键都在语言表中。

来源：Agent · retro.json

建议 02 · Skill 与文档

应用自有 extension 的语言命名空间约定未写明

需人工判断

覆盖测试以 useTranslation('ns') 判断文件是否在插件命名空间翻译；应用自有的 extension 若用自定义翻译 hook（如 useAITranslate）而不写命名空间，就会被当作应用键，必须在应用语言文件里出现。文档没有说明这一取舍。

建议改动

在应用开发 Skill 的 i18n 参考中补一段：把带自定义翻译 hook 的 extension 接入时，要么在调用文件登记 useTranslation('...')（测试跳过，扩展用自身语言表），要么把扩展语言表并入应用语言文件（测试校验）；两种做法都可，但要在应用里保持一种。

来源：Agent · retro.json

建议 03 · Skill 与文档

种子/迁移跨文件复用应用内模块时的相对导入约定未写明

需人工判断

种子与迁移由数据库任务加载器以原生 import() 加载，相对 .js 说明符无法解析到 .ts 源。把权限集定义放在 database/seed-data 并被种子复用时才暴露；此前模板的种子都只导入外部包，没有覆盖这个场景。

建议改动

在 migrations/seeds 参考中补一段：种子或迁移若要引用应用内相对模块，应使用 .ts 扩展名（项目已启用 rewriteRelativeImportExtensions，构建会重写为 .js），或把定义内联，避免依赖开发期的 .js→.ts 转译。

来源：Agent · retro.json
