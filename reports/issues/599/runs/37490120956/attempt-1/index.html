本轮修复唯一已观察到的失败：Migration 中集合构建器把索引选项对象误当作字段参数传给 index()。

问题 01 · 修复阶段

create_project_materials 迁移类型检查失败 (TS2353)

本任务已处理

tsconfig.server.json 下 tsc 报 database/main/migrations/202609200001_create_project_materials.ts(38,18): error TS2353: Object literal may only specify known properties, and 'name' does not exist in type 'string[]'。

原因（实现者自述）
在项目资料集合上写成 collection.foreignKey('ownerId', {...}).index({ name: 'idx_project_materials_owner' })。foreignKey 返回的是 CollectionDefinitionBuilder，其 index 签名为 index(fields: string | string[], options?)，因此以选项对象作为第一个实参会被当作 fields: string[] 校验，对象字面量因只有未知属性 name 而报 TS2353。
处理方式
拆成两个独立调用：collection.foreignKey('ownerId', {...}) 定义外键，collection.index('ownerId', { name: 'idx_project_materials_owner' }) 单独声明命名索引，符合 Builder 的 index(fields, options) 契约。
影响 / 代价：未提供，不估算来源：Agent · retro.json

建议 01 · Skill 与文档

Builder 链式调用的字段/选项区分

需人工判断

nocobase-db Skill 的 Builder 章节给出 collection.index(['orderId','quantity']) 与 foreignKey 的示例，但未提示 foreignKey() 的返回值仍是 CollectionDefinitionBuilder、索引需要单独调用；链式写法容易把 { name } 误当 fields。

建议改动

在 .agents/skills/nocobase-db/SKILL.md 的 Builder 小节补一句：约束方法返回集合构建器而非字段构建器，命名索引须写 collection.index(fields, { name })，不可链式传选项对象。

来源：Agent · retro.json
