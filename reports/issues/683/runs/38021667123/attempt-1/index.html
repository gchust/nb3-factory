问题 06 · verification

format:check failed on the generated runtime config.yml

本任务已处理

`pnpm format:check '!.github/**'` exited 1 with `[warn] config.yml`; Prettier wanted the auth/session secrets written as single-quoted scalars instead of the double quotes `pnpm nocobase config init` writes. Because the check runs before lint/typecheck/test/build, the whole fixed verification stopped at the first stage.

原因（实现者自述）
`config.yml` is a local runtime file generated by `config init` (double-quoted generated secrets), not application source. The factory auto-formatter `format-changes.mjs` explicitly excludes `config.yml` and `create-patch.mjs` protects it, but `prettier . --check` still walked it, so the automatic pass and the fixed check disagreed. `config.yml` is a protected factory file and cannot be edited, and the baseline ships none.
处理方式
Added `/config.yml` (and `/config.toml`) to the application-owned `.prettierignore`, the same mechanism already used for the generated `pnpm-lock.yaml` and `database/*/collections/`. The generated runtime file stays untouched, and the source files under `.github/`, `config.yml`, `.npmrc` and `.gitmodules` were not modified. Re-ran the exact verification command: `pnpm format:check '!.github/**'` -> exit 0, all matched files use Prettier code style.

问题 07 · verification

Built server did not start: it imported a compiled workflow module the workflow artifact build deletes

本任务已处理

`nocobase start` exited 1 reporting `Missing dist/server/standalone.js. Run pnpm build first.` even though `dist/server/standalone.js` existed. The real error was `Cannot find module '.../dist/workflows/order-acceptance/server/order-lifecycle.js' imported from .../dist/server/services/orders.js`.

原因（实现者自述）
The order-acceptance transition was implemented once in `workflows/order-acceptance/server/order-lifecycle.ts`, and server code imported it as `../../workflows/order-acceptance/server/order-lifecycle.js`. `tsc` emits that module to `dist/workflows/...`, but the workflow plugin's `afterServerBuild` hook rebuilds each workflow package as a digest-addressed artifact and deletes the plain compiled tree, so the path no longer exists when the built server runs. The `start.mjs` wrapper catches any `ERR_MODULE_NOT_FOUND` and misreports it as a missing standalone entry, which hid the real specifier.
处理方式
Moved the transition to server-owned `server/services/order-lifecycle.ts`; `orders.ts` and `acceptance.ts` import it directly. A run handler may not import application source, so `ServiceOrderProvider` now registers `OrderAcceptanceService` on the application container under `orderAcceptanceServiceToken`, and the handler resolves it from `options.services`. Because the two sides cannot import one `createServiceToken` result across the artifact boundary, the token is the same object on both sides through `Symbol.for` plus a `globalThis` registry. Updated `server/AGENTS.md` to replace the incorrect `server may import into workflows/` note. Verified with the full `pnpm build` (the built artifact carries no cross-boundary import and the server imports an existing `./order-lifecycle.js`) and a bounded `pnpm start` that listened on `127.0.0.1:13000`; both application test suites that exercise the workflow and the no-plugin boot pass.

建议 01 · documentation

State that workflow run nodes are deferred

可自动化

The workflow authoring guidance describes run handlers as if triggering the workflow performs the work before it returns. In practice the processor defers run nodes, so any route that must report the finished effect has to wait for the run itself.

建议改动

Add a sentence to the workflow skill's run-instruction section: `run` nodes execute after the processor yields, so `trigger` resolves before the handler has changed anything; a caller that needs the finished result must observe the run.

来源：Agent · retro.json

建议 02 · 工具与构建

Temporary test application cannot resolve a workflow artifact's external imports

可自动化

`createAppTest` materializes a source workflow under its temporary directory, which has no `node_modules`, so a run handler importing an external package fails to resolve even though the same import works in the workspace.

建议改动

Have `@nocobase/app-testing` link the invoking application's `node_modules` into the temporary application directory (or resolve artifact imports against the invoking root) so a source workflow that runs in development also runs in an application test.

来源：Agent · retro.json

建议 03 · documentation

Note the explicit-extension requirement for materialized sources

可自动化

Relative imports inside a workflow package and along a chain loaded by the application test loader are executed as TypeScript by Node's native type stripping, which requires explicit extensions; extensionless specifiers pass the checker but fail at run time.

建议改动

Document the explicit `.ts` extension requirement for these two chains, alongside the existing note that the server build rewrites those extensions.

来源：Agent · retro.json

建议 04 · 工具与构建

`eslint . --fix` rewrites factory-owned `.github/` files

可自动化

Running the application's `pnpm lint` with `--fix` also formats the factory harness under `.github/`, which this task forbids changing; the autofix pass modified 17 of its test scripts before they were reverted.

建议改动

Make the application lint config ignore `.github/`, or instruct agents to pass explicit application paths to `eslint --fix`, so an autofix pass cannot touch harness-owned files.

来源：Agent · retro.json

建议 05 · 工具与构建

format-changes.mjs and format:check disagree about config.yml

可自动化

The factory auto-formatter `.github/scripts/format-changes.mjs` deliberately filters out `config.yml` (with `.npmrc` and `.gitmodules`), but the fixed check `pnpm format:check '!.github/**'` runs Prettier over the whole tree and includes it. A locally generated `config.yml` therefore always fails the first fixed check even though the auto-formatter cannot and should not fix it, costing every build a repair round.

建议改动

Make the two agree: either exclude `config.yml`/`config.toml` in the format check as well (for example by reading them from `.prettierignore`, or by adding a `--ignore-path`-compatible entry), or have the check skip the same protected runtime files the auto-formatter and `create-patch.mjs` already exclude.

来源：Agent · retro.json

建议 06 · 工具与构建

`nocobase start` misreports an application module resolution failure as a missing build entry

可自动化

The start wrapper catches any `ERR_MODULE_NOT_FOUND` and prints `Missing dist/server/standalone.js. Run pnpm build first.` even when `dist/server/standalone.js` exists and the unresolved module is an application import. The message points diagnosis at the build output instead of the actual missing specifier, and it was the only browser-facing symptom of the real failure.

建议改动

Print the missing-standalone message only when the entry file itself is absent; otherwise surface the underlying `ERR_MODULE_NOT_FOUND` specifier and importer.

来源：Agent · retro.json

建议 07 · documentation

A composite action must grant at least one non-composite action

可自动化

defineCompositeResource validates each action at definition time and throws TypeError: Composite resource action <name> grants nothing for an action with no grants; a composite may also not grant another composite. This surfaced only at suite import, not in type checking, because the failure is a runtime validator.

建议改动

State in the authorization guidance that every composite action must grant at least one non-composite permission, and that a capability which grants no business data (a settings surface) belongs on a page or settings resource action, not on a composite.

来源：Agent · retro.json

建议 08 · documentation

An unrestricted record scope is a read node with scope:true

可自动化

A composite decision conditions.database value is a RepositoryPolicy. The built-in allRecords scope resolves to { scope: true, fields, relations } rather than to a bare true, so code that distinguishes a team-wide view from a row-scoped one must test read === true || read.scope === true.

建议改动

Add that shape to the database authorization reference so a consumer does not mistake the wrapped unrestricted read node for a scope.

来源：Agent · retro.json

建议 09 · 工具与构建

Permission-set seeds only insert an absent set

需人工判断

database/seed-data/permission-sets.ts writes a set once and skips it when it already exists, so adding a page grant (such as a new settings page) does not reach an installation that already seeded its supervisor set; only a fresh install or an administrator edit picks it up.

建议改动

Give seeded permission sets a reconcile path for additive grants, or document the migration step an added page grant requires on an existing installation.

来源：Agent · retro.json

建议 10 · documentation

A uuid primary key declared without a default must be supplied by the caller

需人工判断

The service_order_files collection is the only one whose id is collection.uuid("id").primary().notNull() with no default; the Collection Builder emits no generator, so an insert that omits id fails with NOT NULL constraint failed at run time and surfaces as an opaque 500. Every other collection used increments("id") and did not show this.

建议改动

State in the database reference that a uuid primary key has no database default and therefore either needs an explicit default in the migration or an id the caller always writes, and that omitting it fails at insert time rather than at build or type-check time.

来源：Agent · retro.json

建议 11 · documentation

A composite action field list is hand-maintained and can silently forbid a field a transition writes

需人工判断

returnOrder ran under the confirm action but wrote returnReason, which ORDER_CONFIRM_FIELDS did not list, so a correct business transition failed with FIELD_WRITE_FORBIDDEN. Type checking cannot see the mismatch because the field list is plain data consumed at run time.

建议改动

In the authorization guidance, call out that a transition must be given a field list that includes every field it writes, and prefer reusing a transition whose action already lists them; a missing field is a run-time 403, not a type error.

来源：Agent · retro.json
