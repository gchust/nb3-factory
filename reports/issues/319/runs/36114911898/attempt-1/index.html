问题 01 · 实现阶段

Hyphenated sample usernames are rejected at sign-in by Better Auth

已解决

Seeded accounts (it-handler, it-employee-1, it-employee-2) were created successfully by the seed, but POST /api/auth/sign-in/username returned 422 INVALID_USERNAME ('Username is invalid'); employees could not sign in to reach the page.

原因（实现者自述）
Better Auth's username plugin validates sign-in identifiers with /^[a-zA-Z0-9_.]+$/. Hyphens pass the database write but fail that validator, so the failure only appears at the sign-in form, long after the seed reports success.
处理方式
Renamed the sample accounts to underscore form (it_handler, it_employee_1, it_employee_2) in the server constants and the sample-data seeds, and left a comment explaining the validator constraint. Verified all three accounts sign in and the role-gated flows work end to end.

建议 01 · seed-safety

Sample-data seeds should validate sign-in identifiers

可自动化

The seed inserts accounts directly into the user/account tables, so an identifier Better Auth's username plugin would reject is accepted without warning and only fails later in the browser.

建议改动

Have the users/authentication seed helpers validate usernames with the same rule the configured Better Auth username plugin uses (or expose a shared validator) and fail the seed with a clear message when an identifier could not be used to sign in.

来源：Agent · retro.json
