# Database notes

## Devices schema and installation data

`database/main/migrations/202611010001_create_devices.ts` creates the `devices` table: string `id` primary key,
unique `code`, `name`, `status` defaulting to `available`, nullable `notes`, and `createdAt`/`updatedAt`. It is
immutable history; a later correction is a new migration, never an edit to this one.

`database/main/seeds/202611010002_seed_devices.ts` is a **required** seed, not a `sample: true` one. The factory
harness installs an application with `pnpm nocobase db apply`, which runs migrations and required seeds but does not
set `APP_SAMPLE_DATA` and does not run `db sample`, so a sample seed would leave the ledger empty. The seed checks for
an existing code before writing and uses fixed ids, so applying it twice changes nothing and it never overwrites an
operator's edits.

`database/main/collections/` is generated by `pnpm nocobase db apply`; never edit it by hand.

Tests: `tests/logic/devices-migration.test.ts` verifies the schema and rollback with `describeMigration()`, and
`tests/logic/devices-seed.test.ts` verifies the two seeded devices and that replaying the seed neither duplicates nor
overwrites them.
